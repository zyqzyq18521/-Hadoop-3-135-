老汤 Hadoop3 课程复盘，搞懂 Hadoop3 纠删码与新特性
Hadoop 3 发布多年，但不少团队仍停留在 Hadoop 2 的使用习惯里：副本数默认 3、NameNode 单点靠外部方案兜底、小文件问题靠事后治理。学完老汤的 Hadoop3 课程后，我最大的感受是：Hadoop 3 不是一次小版本升级，而是在存储效率、高可用和扩展性上做了系统性补强。这篇复盘围绕纠删码和几个关键新特性，把课程里最值得带走的内容梳理清楚。

一、纠删码：Hadoop 3 最核心的存储变革
Hadoop 2 靠多副本保证可靠，默认 3 副本意味着每存 1TB 数据要占 3TB 空间，存储成本高。Hadoop 3 引入纠删码（Erasure Coding），用校验块替代部分副本，在同等可靠性下显著降低存储开销。

课程讲得很透的一点是：纠删码不是“副本的简单替代”。它把数据切分成若干数据块，再生成校验块，常见策略如 6 个数据块加 3 个校验块，允许一定数量的块丢失后仍能恢复。相比 3 副本，存储开销从 3 倍降到约 1.5 倍，冷数据和归档场景收益尤其明显。

但课程也反复提醒边界：纠删码恢复需要读取多个块并计算，恢复成本高于副本；对延迟敏感的热数据，多副本仍然更合适。所以 Hadoop 3 支持按目录或文件设置存储策略，冷热分层、按需选择，才是正确用法。这一点让我理解了“技术不是越新越好，而是匹配场景”。

二、NameNode 高可用：从外部方案走向原生支持
Hadoop 2 时代，NameNode 高可用往往依赖外部组件和复杂配置。Hadoop 3 在这方面继续完善，支持多个 NameNode 的联邦与高可用能力增强，让大规模集群的元数据管理更稳。课程强调，理解 NameNode 的职责和瓶颈，比记住配置项更重要：元数据量、编辑日志、检查点机制，决定了集群能扩到多大规模。

三、YARN 与资源调度：更细粒度的管理
Hadoop 3 在 YARN 上增强了资源管理能力，支持更灵活的调度策略和容器资源类型。课程没有停留在参数讲解，而是让我们理解资源队列、权限隔离和弹性分配在真实集群中的意义。资源调度设计不好，再强的计算能力也会被争抢和浪费拖垮。

四、小文件与存储效率：工程视角的补强
小文件一直是 HDFS 的老大难。Hadoop 3 虽然没有一招解决所有小文件问题，但在存储策略、归档和元数据管理上提供了更多手段。课程把这些手段放进真实场景讲：什么情况该合并、什么情况该用归档、什么情况该在写入端就控制文件大小。治理小文件，关键在源头设计，而不是事后补救。

五、复盘收获：从“会用”到“会选”
老汤这门课最有价值的地方，是始终围绕“为什么这样设计、什么场景适用”来讲。纠删码、高可用、YARN 增强、存储策略，这些特性单独看是知识点，放在一起就是一套集群设计方法：根据数据温度选存储策略，根据规模选高可用方案，根据业务选调度方式。

复盘下来，我对 Hadoop 3 的理解从“版本号更新”变成了“成本、可靠性和扩展性的再平衡”。纠删码降低存储成本但抬高恢复代价，高可用增强稳定性但增加运维复杂度，新特性都有适用边界。搞懂这些取舍，才算真正搞懂 Hadoop 3。课程给的不是配置手册，而是一套做集群决策的思维框架，这比记住多少参数更有长期价值。
